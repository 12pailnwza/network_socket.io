# ตัวเลือกโฮสต์สำหรับเว็บแชท

ตรวจสอบ: 2 พฤศจิกายน 2026  
สถานะ: ผู้ใช้ยืนยัน SQLite โฮสต์ฟรีและไม่ใช้บัตรเท่านั้น จำนวนออนไลน์พร้อมกันไม่ถึง 10 คน ยังไม่ได้สมัครบริการหรือ deploy ผลสำรวจ alwaysdata และ Render + Neon ด้านล่างเป็นข้อเสนอเดิมที่ไม่ตรงเงื่อนไขล่าสุด

## ตัวเลือกใหม่ที่ไม่ใช้บัตร: ยังต้องทดสอบ

### Weeny Free — ตัวเลือกที่ควรประเมินด้าน SQLite ก่อน

- [หน้า Free](https://weeny.cloud/free) ระบุว่าไม่ต้องใช้บัตร และมีที่เก็บ SQLite ถาวรใน WEENY_DATA_DIR ซึ่งไม่ถูกแทนที่ตอน deploy
- [หน้าราคา](https://weeny.cloud/pricing) ระบุ free server 1 vCPU / RAM 1 GB, ใช้ URL ที่บริการให้, พักเมื่อเงียบประมาณ 30 นาที มี badge และโควตารับบัญชีฟรีจำกัด ถ้าเต็มอาจต้องรอ ไม่ใช่การรับประกันว่ามีเครื่องฟรีให้สมัครได้ทันที
- [เอกสาร](https://weeny.cloud/docs) มีแนวทาง Node + SQLite และแยกโค้ดจากข้อมูลถาวร จึงดูเข้ากับโครงระบบนี้
- ยังไม่พบข้อความยืนยันพฤติกรรม WebSocket proxy/timeout จากแหล่งที่อ่าน จึงต้องทดสอบ WSS upgrade, cookie, reconnect และการพักเครื่องจริงก่อนเลือกใช้งาน
- เป็นบริการขนาดเล็กที่ [เงื่อนไข](https://weeny.cloud/terms) ระบุว่ายังไม่มี SLA ต้องมี backup ของเราเอง

### Wispbyte Free — ตัวเลือกสำรองที่ต้องตรวจการเปิดเว็บ

- [หน้าเว็บทางการ](https://wispbyte.com/) ระบุไม่ใช้บัตร, RAM 512 MB, disk 1 GB และรองรับ Node.js โดยต้องล็อกอินหน้าจัดการอย่างน้อยทุก 14 วัน
- [คู่มือจัดการเซิร์ฟเวอร์](https://wispbyte.com/kb/server-management) มีจัดการไฟล์และ subdomain แบบ beta เฉพาะที่เปิดให้ใช้ ส่วน backup ขึ้นกับแพ็กเกจ
- ยังไม่ได้ยืนยันจากเอกสารที่อ่านว่าบัญชีฟรีของผู้ใช้จะได้ public HTTPS/WSS ที่เหมาะกับแชท และ SQLite จะคงอยู่ตามเงื่อนไข lifecycle ใดบ้าง ต้องตรวจในบัญชีและทดสอบ restart/deploy ก่อนตัดสินใจ

ทั้งสองรายเป็นตัวเลือกสำรวจ ไม่ใช่ผลทดสอบว่าระบบใช้งานได้แล้ว หากไม่ผ่านการทดสอบหรือไม่มีโควตาฟรี ต้องรายงานข้อจำกัดและหาตัวเลือกต่อ ไม่เปลี่ยนไปใช้แผนเสียเงินหรือใช้บัตรโดยอัตโนมัติ

## ตัวเลือกเดิมที่ตัดออกจากแนวทางหลัก: alwaysdata Free

ข้อมูลจากเอกสารทางการ ณ วันที่ตรวจสอบ:

- แพ็กเกจ Free สำหรับใช้ส่วนตัว ราคา €0 มี SSD 1 GB, RAM 256 MB และ CPU 1/4 พร้อมเก็บ backup ย้อนหลัง 3 วัน ตาม [หน้าแพ็กเกจ](https://www.alwaysdata.com/en/offers/)
- รองรับ Node.js รวมเวอร์ชัน 24 ตาม [เอกสาร Node.js](https://help.alwaysdata.com/en/docs/web-hosting/languages/nodejs/configuration/)
- มี [ตัวอย่าง WebSocket ด้วย Node.js/ws](https://help.alwaysdata.com/en/blog/2023-03-14-hold-on-to-your-socks-high-speed-data-stream-hosting-with-websockets/) และระบุให้ deploy เป็น Web Site ไม่ใช่บริการเบื้องหลังประเภท Services จึงต้องแยกความหมายจากข้อจำกัดที่ Free ห้ามรัน Services
- มีไฟล์ใน home directory และ backup ไฟล์รายวันตาม [เอกสารสำรองข้อมูล](https://help.alwaysdata.com/en/docs/web-hosting/backups/) จึงเป็นตัวเลือกสำหรับเก็บ SQLite บนเซิร์ฟเวอร์ได้ ต่างจากดิสก์ชั่วคราวของ Render Free ทั้งนี้ยังต้องทดสอบสิทธิ์เขียนไฟล์และการคงข้อมูลเมื่อ restart/deploy จริง
- Free ใช้ URL ภายใต้ alwaysdata.net และใช้เชิงพาณิชย์ไม่ได้ บัญชีใหม่ต้องเข้าหน้าจัดการอย่างน้อยทุก 120 วันเพื่อหลีกเลี่ยงการพักบัญชี ตาม [ข้อจำกัดและการพักบัญชี](https://help.alwaysdata.com/en/docs/admin-billing/profile/suspension/)
- [หน้าสมัคร](https://www.alwaysdata.com/en/register/) แสดงขั้นตอนยืนยันบัตรเครดิต/เดบิตและระบุว่าไม่เรียกเก็บค่าธรรมเนียม แม้หน้าประชาสัมพันธ์บางหน้าจะระบุว่าสมัครได้โดยไม่ใช้บัตร จึงยังไม่รับประกันว่าจะสมัครโดยไม่ใช้บัตรได้ ห้ามพยายามหลีกเลี่ยงขั้นตอนยืนยัน

ข้อประเมินสำหรับโปรเจกต์นี้:

1. ดูเข้ากับเงื่อนไข Node.js + WebSocket + ไฟล์ SQLite ถาวร และเหมาะแก่การทดลองก่อน แต่ยังไม่ใช่โฮสต์ที่ยืนยันเลือกแล้ว
2. RAM และพื้นที่ค่อนข้างน้อย ควร build React บนเครื่องพัฒนาหรือระบบ build แยก แล้วส่งเฉพาะไฟล์ที่ต้องรันและ dependency ฝั่งเซิร์ฟเวอร์ขึ้นไป ไม่ยกโฟลเดอร์พัฒนาทั้งหมดขึ้นโฮสต์
3. โฟลเดอร์ฐานข้อมูลต้องอยู่นอกโฟลเดอร์ที่ถูกแทนที่ระหว่าง deploy และต้องตั้ง DATABASE_PATH เป็นตำแหน่งถาวรชัดเจน
4. สร้าง backup SQLite ที่สอดคล้องกันด้วย SQLite backup API หรือวิธีที่รองรับ WAL ไม่ถือว่าคัดลอกเฉพาะไฟล์ .sqlite ขณะมีการเขียนเป็น backup ที่สมบูรณ์เสมอ
5. ตรวจ HTTPS/WSS, cookie, proxy, idle timeout, ฐานข้อมูลหลัง restart และจำนวนผู้ใช้พร้อมกันจริงก่อนสรุปว่าพร้อมสาธิต

ยังไม่ต้องส่งข้อมูลบัตรหรือรหัสผ่านในแชท ผู้ใช้จัดการการสมัครและการยืนยันบัญชีเองเมื่อถึงขั้นเลือกบริการ

## ข้อสรุปล่าสุด: ใช้ SQLite

ผู้ใช้ยืนยันเก็บข้อมูลใน SQLite โดยยังต้องการเข้าใช้งานผ่านอินเทอร์เน็ตและสำรวจตัวเลือกฟรีก่อน ต้องหาเครื่องเซิร์ฟเวอร์ที่มีพื้นที่เก็บไฟล์ถาวร จึงไม่ใช้ SQLite บนดิสก์ชั่วคราวของ Render Free และไม่ย้ายไป Neon PostgreSQL ตามข้อเสนอเดิม

ผู้ใช้ขอให้หาโฮสต์ฟรีและไม่ใช้บัตร จึงให้ความสำคัญกับโฮสต์ที่เก็บไฟล์ถาวร แทนการรันบนเครื่องของผู้ใช้ ดูตัวเลือกใหม่ด้านบน ยังไม่ได้เลือกบัญชีผู้ให้บริการหรือเปลี่ยนการตั้งค่าเครือข่ายใด ๆ

## เป้าหมาย

เข้าใช้ผ่านอินเทอร์เน็ตตั้งแต่เวอร์ชันแรก รองรับ Node.js + WebSocket และเก็บบัญชี/ประวัติถาวร โดยเริ่มจากแพ็กเกจฟรี ข้อเสนอด้านล่างเหมาะกับการทดลองและสาธิตโปรเจกต์ ไม่ใช่คำรับประกันการให้บริการตลอดเวลา

## ข้อเสนอเดิมที่ไม่ได้เลือก: Render Free + Neon Free

```text
Browser ── HTTPS / WSS ── Render: React + Node.js / ws
                                      │
                                      ├── Neon: PostgreSQL
                                      └── AI provider (เลือกภายหลัง)
```

### เว็บและเซิร์ฟเวอร์: Render Free

- รองรับ Node.js และ WebSocket จึงใช้แนวทางเซิร์ฟเวอร์ปัจจุบันต่อได้
- บริการพักหลังไม่มี traffic เข้า 15 นาที โดยข้อความ WebSocket ที่เข้ามานับเป็น traffic ด้วย เมื่อปลุกอาจใช้เวลาประมาณหนึ่งนาที
- ไฟล์ที่เขียนในเครื่องบริการหายได้เมื่อ restart, redeploy หรือพักบริการ และแพ็กเกจฟรีไม่มี persistent disk จึงไม่ใช้ SQLite เป็นฐานข้อมูลถาวรบนบริการนี้
- มีโควตา runtime ฟรี 750 ชั่วโมงต่อ workspace ต่อเดือน รวมทั้งโควตา bandwidth/build; เมื่อไม่มีวิธีชำระเงิน การใช้เกินอาจทำให้บริการหรือการ build ถูกระงับตามประเภทโควตา
- ฐานข้อมูล Render Postgres ฟรีมีอายุ 30 วัน จึงไม่ใช่ตัวเลือกหลักสำหรับเก็บประวัติระยะยาวของโปรเจกต์นี้

แหล่งข้อมูล: [Render Free](https://render.com/docs/free), [WebSocket บน Render](https://render.com/docs/websocket), [การ deploy และ URL](https://render.com/docs/your-first-deploy)

### ฐานข้อมูล: Neon Free

- เป็น PostgreSQL แยกจากเครื่องรันแอป ข้อมูลจึงไม่ผูกกับไฟล์ชั่วคราวของ Render
- หน้าราคาระบุ Free ไม่มีระยะเวลาทดลองหมดอายุ และไม่ต้องใช้บัตรเครดิต
- โควตาต่อโปรเจกต์ที่ตรวจพบ: ข้อมูล 1 GB, compute 100 CU-hours ต่อเดือน และ public network transfer 5 GB ต่อเดือน
- compute พักเมื่อไม่มีการใช้งาน 5 นาที การพัก compute ไม่ได้ลบข้อมูล
- เมื่อ compute/network ถึงโควตา บริการ compute อาจพักจนรอบใหม่หรืออัปเกรด; ไม่ควรรับประกันว่าจะฟรีและพร้อมใช้งานได้ไม่จำกัด

แหล่งข้อมูล: [Neon Pricing](https://neon.com/pricing), [ข้อจำกัด Free plan จากคลังเอกสารทางการ](https://github.com/neondatabase/website/blob/main/content/faqs/free-plan-limits-and-quotas.md)

## ตัวเลือกที่ตรวจสอบแต่ยังไม่แนะนำเป็นอันดับแรก: Koyeb

เอกสารมี Free Instance และรองรับ WebSocket แต่ FAQ การสมัครระบุว่าต้องใช้บัตร มีการกันวงเงิน $29 และเรียกเก็บค่าบริการตามสัดส่วนของแผนที่เลือกตอนสมัคร จึงไม่แนะนำให้เริ่มสมัครโดยถือว่าจะไม่มีค่าใช้จ่าย ข้อสรุปนี้เป็นการประเมินให้ตรงกับเป้าหมายเริ่มฟรีของผู้ใช้

แหล่งข้อมูล: [Koyeb Pricing FAQ](https://www.koyeb.com/docs/faqs/pricing), [WebSocket และ TLS](https://www.koyeb.com/docs/reference/edge-network)

## ผลต่อการออกแบบและการพัฒนาถ้าเลือก Render + Neon

1. เปลี่ยน storage layer จาก node:sqlite เป็น PostgreSQL พร้อมปรับ schema และคำสั่ง SQL
2. เก็บ session และตำแหน่งอ่านล่าสุดใน PostgreSQL ด้วย เพื่อให้ restart แล้วใช้งานต่อได้
3. เสิร์ฟหน้าเว็บ API และ WebSocket ภายใต้ origin เดียวกัน ใช้ HTTPS/WSS และ cookie แบบ Secure
4. เชื่อมต่อฐานข้อมูลด้วย TLS ตามข้อกำหนดผู้ให้บริการ และจำกัดจำนวน connection ให้เหมาะสม
5. รองรับ reconnect แบบเว้นระยะเพิ่มขึ้น โหลดข้อความตกหล่น และกันข้อความซ้ำจาก retry
6. ทดสอบการเชื่อมต่อหลังแอปพัก ฐานข้อมูลพัก และ deploy ใหม่ ไม่ตรวจเฉพาะตอนบริการกำลังทำงาน
7. เก็บขั้นตอนตั้งค่า สำรองข้อมูล และตรวจโควตาไว้ใน README

ยังไม่ต้องแก้โค้ดในช่วงวางแผนนี้ โค้ดร่างปัจจุบันยังเป็น SQLite และยังไม่พร้อมนำขึ้น Render ตามแนวทางนี้ทันที

## สิ่งที่เคยต้องเตรียมสำหรับข้อเสนอเดิม (ไม่ใช่รายการที่ต้องทำตอนนี้)

- บัญชี Render และ Neon หากยืนยันเลือกแนวทางนี้
- ที่เก็บซอร์สโค้ดสำหรับเชื่อมการ deploy เช่น GitHub โดยเลือกวิธีเชื่อมต่ออีกครั้งในขั้นติดตั้ง
- ค่า DATABASE_URL จาก Neon ให้ตั้งใน secrets/environment ของโฮสต์ ไม่ส่งในแชทหรือ commit ลง Git
- บัญชีและ API key ของ AI provider ที่จะเลือกภายหลัง โฮสต์และฐานข้อมูลฟรีไม่ได้แปลว่า AI จะใช้ฟรีด้วย

การสำรวจนี้ยังไม่ได้พิสูจน์ประสิทธิภาพ จำนวนผู้ใช้พร้อมกัน หรือความเสถียรจากการ deploy จริง ต้องทดสอบเมื่อเริ่มพัฒนาและเลือกบัญชีบริการแล้ว
