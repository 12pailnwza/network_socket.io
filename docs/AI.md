# AI สรุปแชท: ตัวเลือกฟรี

ตรวจสอบข้อมูล: 2 พฤศจิกายน 2026  
สถานะ: หลังคุยเรื่อง OpenRouter และให้เริ่มสร้าง โค้ดปัจจุบันเตรียมใช้ OpenRouter โมเดลฟรี ยังไม่มี API key และยังไม่ได้เรียก AI จริง ส่วน Groq/Gemini ด้านล่างเก็บเป็นข้อมูลเปรียบเทียบเดิม

## การเชื่อมต่อที่สร้างแล้ว: OpenRouter Free

- endpoint ฝั่งเซิร์ฟเวอร์ `/api/summary` เรียก `https://openrouter.ai/api/v1/chat/completions`
- ตั้ง `OPENROUTER_API_KEY` และ `AI_MODEL=openrouter/free` หรือ model ID ที่ลงท้าย `:free` โค้ดปฏิเสธ model ID แบบเสียเงิน
- [ข้อมูลโมเดลฟรีทางการ](https://openrouter.ai/collections/free-models) ระบุข้อจำกัดสำหรับ free variants และโควตาบัญชีที่ไม่ซื้อเครดิต ต้องตรวจอีกครั้งเมื่อใช้งานจริง โควตาใช้รวมทุกคนผ่าน key กลางของเซิร์ฟเวอร์
- ให้ผู้ใช้ยินยอมส่งข้อความไปประมวลผลภายนอกก่อน มี cache ตามห้อง/ข้อความล่าสุด/โมเดล และป้องกันการเรียกถี่ ไม่ส่งข้อความไป AI อัตโนมัติ
- ทดสอบด้วย provider จำลองแล้ว ทั้ง success/cache, quota 429 และการถอนสิทธิ์ระหว่างรอผล แต่ยังไม่ทดสอบผู้ให้บริการจริง
- ดูวิธีตั้งค่าและข้อจำกัดใน [README](../README.md#ต่อ-openrouter-ฟรี)

## ข้อเสนอแรก: Groq Free

- มี Free tier แยกจาก Developer tier โดย [เอกสาร Billing](https://console.groq.com/docs/billing-faqs) ระบุว่าต้องเพิ่มวิธีชำระเงินเมื่อต้องการอัปเกรดเป็น Developer จึงให้ทดลองเฉพาะ Free และไม่อัปเกรด/เพิ่มบัตร
- [คำตอบจากทีม Groq](https://community.groq.com/t/do-i-get-charged-for-anything-on-the-groq-free-plan/832) ระบุว่า Free ไม่คิดค่าใช้จ่าย เมื่อเกินโควตาจะตอบ 429 แทนการคิดเงิน
- ใช้ [รูปแบบ API ที่รองรับ OpenAI client](https://console.groq.com/docs/openai) ซึ่งสอดคล้องกับแนวทาง HTTP request ของโค้ดร่าง แต่ยังต้องเลือกโมเดลและทดสอบ request จริง การรองรับรูปแบบ API นี้ไม่ได้หมายความว่าต้องสมัครหรือจ่ายเงินให้ OpenAI
- [Rate limits](https://console.groq.com/docs/rate-limits) จำกัดทั้งจำนวนคำขอและ tokens ระดับองค์กร แต่ละโมเดลและบัญชีอาจต่างกัน ต้องดูโควตาในบัญชีจริง ไม่ถือว่าผู้ใช้ไม่ถึง 10 คนแล้วจะไม่มีวันเกินโควตา
- ทดลองโมเดลข้อความที่เปิดให้ใช้ในบัญชี Free ณ เวลาทดสอบ โดยประเมินการสรุปทั้งไทยและอังกฤษก่อนเลือก ไม่ยืนยัน model ID ล่วงหน้าจากรายชื่อที่อาจเปลี่ยน
- ตรวจ [นโยบายข้อมูล](https://console.groq.com/docs/your-data) และแจ้งใน UI ก่อนส่ง transcript ไปยังผู้ให้บริการภายนอก

## วิธีใช้ในระบบที่เสนอ

1. สมาชิกเปิดห้องที่ตนมีสิทธิ์อ่านและกด Summarize
2. หน้าเว็บแจ้งว่าจะส่งข้อความล่าสุดในห้องไปประมวลผลภายนอก
3. เซิร์ฟเวอร์ตรวจ session, สมาชิก และสถานะห้อง รวมกรณีออกจากกิลด์หรือกิลด์ถูกยุบ
4. เลือกข้อความล่าสุดตามขอบเขตที่แสดงให้ผู้ใช้ทราบ จำกัดจำนวนข้อความและขนาดรวม เพื่อไม่เกิน input quota ไม่ส่งรหัสผ่าน session หรือข้อมูลบัญชีอื่นไปด้วย
5. เรียก AI จากเซิร์ฟเวอร์โดยอ่าน API key จาก environment เท่านั้น
6. แสดงผลเป็นสรุปที่ AI สร้าง แยกจากข้อความผู้เล่น ให้ผู้เรียกอ่านเองก่อนโดยไม่ส่งลงห้องอัตโนมัติ
7. ถ้าเกิด timeout หรือ 429 แสดงข้อความภาษาอังกฤษให้ลองใหม่ภายหลัง โดยแชทปกติยังใช้งานต่อได้

ข้อเสนอเพื่อลดโควตา: เรียกเมื่อกดเท่านั้น จำกัดความถี่ต่อผู้ใช้และทั้งระบบ รวมคำขอซ้ำของ transcript เดียวกัน และไม่ส่งข้อความใหม่ทุกข้อความเข้า AI

## ทางเลือกสำรองที่ยังไม่เลือก: Gemini API Free tier

[หน้าราคาทางการ](https://ai.google.dev/gemini-api/docs/pricing) มี Free tier สำหรับบางโมเดลและมีข้อจำกัด โดยระบุว่าข้อมูลของ Free tier ใช้ปรับปรุงผลิตภัณฑ์ได้ ต้องตรวจโมเดล ประเทศ บัญชี โควตา และเงื่อนไขก่อนเลือก ไม่ถือว่าทุกโมเดลใช้ฟรีได้

## สิ่งที่ยังต้องเตรียมเมื่อเริ่มต่อบริการ

- บัญชี Free ของผู้ให้บริการและ API key โดยไม่ส่ง key ในแชทหรือ commit ลง Git
- เลือกโมเดลหลังทดสอบกับข้อความจำลองที่ไม่มีข้อมูลส่วนตัว
- กำหนดช่วงข้อความที่จะสรุปและข้อความแจ้งการประมวลผลภายนอก
- บันทึกผู้ให้บริการ model ID ขอบเขตข้อความ และตัวอย่างผลจริงสำหรับ Implementation Explanation
